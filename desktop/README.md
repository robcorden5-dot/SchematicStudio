# SchematicStudio desktop (Tauri)

The website's editor in a native window, with projects and libraries kept as files on the computer.
**The website is not touched.** This folder only *reads* the site's files and builds its own copy in `src/`.

```
desktop/
  scripts/sync.mjs          copies the site's front end into src/, turns index.php into index.html, bundles Konva
  scripts/php-to-html.mjs   the small index.php -> index.html converter (stops with a message on PHP it doesn't know)
  scripts/serve.mjs         tries the desktop build in an ordinary browser (npm run serve)
  shim/desktop-shim.js      stands in for the server inside the app (see below)
  src/                      GENERATED by sync.mjs - what the app loads
  src-tauri/                the Tauri (Rust) shell: window, plugins, permissions, icons
  test/                     shim tests (Playwright, Python)
  .github/workflows/        builds Windows / macOS / Linux installers on GitHub (optional)
```

## How it works

The editor talks to the server with `fetch()` only: projects, parts library, title block designs, symbol libraries, a keep-alive
ping. `desktop-shim.js` answers those same requests from local storage, with the same response shapes, so the editor code is the
website's code, unchanged. It also supplies a native *Save as* dialog (every CSV / JSON export uses it), a print preview that works
without pop-up windows, and opens website links in the system browser.

| Data | Where it lives in the app |
|---|---|
| Projects | `Documents/SchematicStudio/projects/<id>.ssproj` (plain JSON, one file each) |
| Parts library, title block designs | the app's data folder (`parts.json`, `titleblocks.json`) |
| Symbol libraries | bundled in the app (`src/symbol-libraries/`), refreshed on every sync |

`projects/index.json` is only a cache; it is rebuilt from the `.ssproj` files if it is missing or out of step, so files copied in or
removed by hand are picked up.

**This test build is always Pro, with no login and no licence check** (that is a later phase). Account, billing and help links open
the website in the system browser.

## Try it

You need Node 20+ for step 1-2, and Rust plus your platform's Tauri prerequisites for step 3
(<https://v2.tauri.app/start/prerequisites/>).

```
cd desktop
npm install
npm run sync -- "C:\path\to\your\site"     # or put the path in desktop.config.json (see the example)
npm run serve                              # 1. optional: try it in a browser at http://localhost:8123 (data in browser storage)
npm run dev                                # 2. the real app window (sync + tauri dev)
npm run build                              # 3. installers in src-tauri/target/release/bundle/
```

Run `npm run sync` again whenever the website changes. To avoid installing Rust locally, push the folder to GitHub and run the
**Build desktop app** workflow (Actions tab): installers for all three systems come back as downloads. That workflow expects
`desktop/` at the repository root and `src/` committed (sync first).

## What has and has not been tested

Tested here (headless Chromium, `python3 test/shim.test.py` and `test/rebuild.test.py`): the page converts from `index.php` with
no PHP left and matches PHP's own rendering; every endpoint the editor uses, in browser mode and against a fake Tauri file system;
the Save dialog and cancel; link handling; the print overlay; index rebuild from files.

**Not tested** (needs a real build): the Rust shell and plugin permissions, the installers, WebView2 / WKWebView behaviour for
Konva, drag-and-drop and printing (the print preview uses the page's own print call and is the first thing to check on macOS), and
the real Konva (the sandbox could not download it; `npm install` fetches it on your machine).
